# GP 因子发现引擎架构

## 总览

GP 因子发现采用**两阶段适应度评估**：IC 快速评估（并行，全员参与） + 真实回测验证（并行，每代仅对 top-5 精英执行）。

## 整体流程

```
evolve() 每代执行：
  ┌─────────────────────────────────────────────────────┐
  │ 1. 锦标赛选择 + 交叉 + 变异                         │
  │ 2. IC 评估 400 个个体（ThreadPool，8 线程）   ~15s │
  │ 3. 按 IC 适应度排序                                 │
  │ 4. backtest_callback(种群, 代数)                    │
  │    ├─ 取前 5 名通过验证的精英                        │
  │    ├─ 批量编译 + 计算因子值                          │
  │    ├─ 跑 5 个 solo 回测（ThreadPool，4 线程） ~2s   │
  │    └─ 融合：适应度 = 0.7×IC + 0.3×Sharpe（归一化）  │
  │ 5. 重新排序种群（回测结果可能改变排名）               │
  │ 6. 更新名人堂，打日志，检查早停                      │
  └─────────────────────────────────────────────────────┘

GP 结束后逐代后处理：
  ┌─────────────────────────────────────────────────────┐
  │ 1. 验证候选因子（样本外 walk-forward IC）            │
  │ 2. 正交化 + 多样性过滤                               │
  │ 3. Solo 回测（ThreadPool，4 线程）        并行      │
  │ 4. Cumulative 回测（ThreadPool，4 线程）  并行      │
  │    └─ 预计算所有 GP 因子值（一次批量）               │
  │    └─ 每个任务从缓存中取列子集                        │
  │    └─ 若中间有因子被拒绝：重跑后面的组合               │
  │ 5. 对已拒绝因子用完整因子集二次验证        并行      │
  │ 6. 保存 gp_factors.json，生成报告                    │
  └─────────────────────────────────────────────────────┘
```

## 关键设计决策

### IC 适应度（快速，全员 400 个）

- 公式：IC 均值 (0.4) + IC IR (0.2) + 稳定性 (0.2) + 命中率 (0.2)
- **硬拒绝**（直接淘汰，不打回测）：
  - 秩自相关 > 0.95（因子值几乎不变，无选股能力）
  - IC 标准差 < 0.005（IC 恒定为常数）
  - 表达式深度 ≤ 1（过于简单，无信息量）
- 使用 ThreadPoolExecutor（8 线程）——`exec()` 编译出的 Factor 类不可 pickle，但 pandas 会释放 GIL，多线程依然有效

### 回测适应度（慢速，仅 top-5）

- 跑完整 AgentSimulation 回测循环（含 broker、universe filter、T+1、涨跌停限制）
- Sharpe 归一化：`(sharpe + 1) / 4`，截断至 [0, 1]
- 融合公式：`适应度 = 0.7 × IC适应度 + 0.3 × 归一化Sharpe`
- **作用**：过滤 IC 虚高但实际交易无效的因子（例如因子值接近常数、IC 高但无法产生交易信号）

### Cumulative 回测并行化

- 预计算基准因子 + 全部 GP 因子值，一次批量完成
- `BacktestTask.factor_cache`：每个任务只取所需列子集，避免重复计算
- 第一轮：假设全部因子通过，并行跑所有 cumulative 组合
- 若中间某个因子被拒绝：用修正后的因子集合重跑后续组合
- 第二轮（二次验证）：同样并行

### 线程安全

- 使用 ThreadPoolExecutor 而非 ProcessPoolExecutor（编译后的 Factor 类不可 pickle）
- 每个 worker 创建独立的 AgentSimulation 实例（独立的 accountant、broker、journal）
- 行情数据在所有 worker 间只读共享

## 配置参数

| 参数 | 默认值 | 说明 |
|------|--------|------|
| `max_workers` | 8 | IC 评估线程池大小 |
| `pure_factor_blend_weight` | 0.3 | 回测 Sharpe 在融合适应度中的权重 |
| `backtest.parallel max_workers` | 4 | Solo / Cumulative 回测线程池大小 |
| `crossover_prob` | 0.7 | 交叉概率 |
| `mutation_prob` | 0.3 | 变异概率 |
| `max_auto_corr` | 0.95 | 秩自相关硬拒绝阈值 |
| `wrap_rolling_mutation_weight` | 0.30 | wrap_rolling 变异操作的权重 |

## 日志输出格式

```
Gen   3: best_fitness=0.2341 IC=0.0450 IR=1.230 depth=4 nodes=8 (gp_ts_std_volume_abc123) btSR=1.234 [18.2s]
```

`btSR` 仅在 `backtest_callback` 执行后出现（Sharpe 非零时）。

## 设计逻辑总结

整个架构解决的核心矛盾是 **评估精度 vs 计算开销**：

1. IC 评估（毫秒级）做初筛，排除明显无效的因子
2. 真实回测（秒级）做精筛，排除 IC 虚高但无法交易的假因子
3. 硬拒绝规则在 IC 阶段就过滤掉三类垃圾因子（常值、无统计意义、太简单）
4. 因子值预计算 + 列子集共享避免回测链中的重复计算
5. 纯因子评估（`pure_factor.py`）将因子发现与策略优化解耦，确保评估的是因子本身的选股能力而非策略拟合
